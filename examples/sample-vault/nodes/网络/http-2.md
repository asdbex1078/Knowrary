# HTTP/2

把文本换成**二进制分帧**：请求和响应被切成带流 ID 的帧，一条 TCP 连接上可以同时跑多个流，
彼此交错传输、互不等待。再加上头部压缩（HPACK）和服务端推送。

## 核心内容

**它只解决了一半问题。** 应用层不再排队了，可 TCP 仍然要求字节流有序——
丢一个包，内核就得等它重传，**这条连接上所有的流一起卡住**。
换句话说队头阻塞从应用层掉到了传输层，在丢包率高的网络上反而比开 6 条连接的 HTTP/1.1 更糟。

这正是 [[http-3]] 要换掉传输层的理由。
