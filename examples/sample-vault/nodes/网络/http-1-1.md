# HTTP/1.1

把 HTTP/1.0 的"一个请求一条连接"改成了**长连接**（`Connection: keep-alive`）：
一条 TCP 连接可以连着发好几个请求，省掉了每次三次握手的开销。

## 核心内容

它留下的病根是**一条连接同一时刻只能有一个请求在飞**。管线化（pipelining）想解决这个，
允许不等响应就发下一个请求，但响应**必须按发出的顺序回来**——第一个慢，后面全堵着。
这就是应用层的[[head-of-line-blocking]]，也是浏览器普遍开 6 条连接的原因。

## 关系
- 属于:: [[http]]
- 依赖:: [[tcp]] — 文本协议，靠 TCP 保证有序可靠
- 演化为:: [[http-2]] (2015) — 换成二进制分帧，一条连接跑多个流

## 线头
- 管线化几乎没被真正启用过，各家浏览器默认都关着——为什么？
