## 要求

1. **分 2～5 个子领域**，每组 5～10 个点，整份不超过 30 个。
   组名是**子领域的名字**（例如「注意力结构」「训练范式」「推理与部署」），
   不要写成"第一阶段""入门篇"——这张图不排先后。
2. **一个点 = 一个可以独立复习的概念**，不是一本书、不是一个章节。
3. **只铺主干。** 这个领域里"不知道它就等于不懂这个领域"的那些点才进来；
   边角料、具体产品名、一次性的工程细节不要。宁可少铺，漏了我以后随时能加，
   凑数的点会让我误以为这个领域已经铺满了。
4. **上面「这份计划里已经有的点」和「已有的节点」里出现过的概念，必须原样复用那个 id**，
   **也不要另起一个近义的新名字**（`RNN` 和 `RNN与长程依赖`、`BPE分词` 和 `子词分词-BPE`
   这种算同一个点）——否则同一个知识点会被建两遍。宁可不列，也不要列近义词。
5. `id` 同时是将来 Markdown 的文件名：**不能含空格**，也不能含 `/ \ : * ? " < > |`。
6. `why` 写一句话：**这个点在这个领域里占什么位置**（它是哪一块的地基、或者它解决了什么问题），
   不要写"很重要"这种废话。
7. **`load`（负荷）三档**，按"看懂并且能复述出来"要花多久估：
   `轻` = 一小时内；`中` = 半个下午；`重` = 要动手推导或写代码，得一整天。
   这是我排时间表的唯一依据，别一律填「中」。
8. **`field`（领域）**：这张图落在哪个顶层领域。上面「已有的领域」里有合适的就**原样复用**，
   没有再起一个短名字（它会成为一个目录，所以要短、要稳）。
