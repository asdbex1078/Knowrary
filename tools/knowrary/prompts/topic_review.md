## 你要做的

挑出**值得改的地方**，每条意见带一个我能一键采纳的改法。没问题就少说，别凑数；最多 12 条。

四种意见（kind）：
1. `fact`：框上的字或悬停说明**写错了**（数字、顺序、名字、因果）。`target` 是那个框的 id，
   `fix` = `{"field": "text" 或 "tip", "value": "改成什么（完整替换后的文字）"}`。
   只挑有把握的事实错误；措辞偏好不算。
2. `missing`：结构上**缺了一块**（比如磁盘布局少了逻辑块位图）。`target` 是它该放进的大框 id（没有合适的大框就省略），
   `fix` = `{"shape": "rect|frame|text|ellipse|triangle|diamond|cylinder", "text": "框上写什么", "tip": "悬停说明（可空）"}`。
3. `upgrade`：某个框值得**升级成知识点**（它是一个值得单独复习的概念）。`target` 是那个还没升级的框 id，
   `fix` = `{"node": "库里已有的知识点 id，没有就写 null", "name": "要新建时建议的名字"}`。
   只有上面列出的知识点 id 才能填进 `node`。
4. `link`：两个东西之间**该连一条线**（或现在连反了 / 连错了要补一条对的）。
   `fix` = `{"from": {"kind": "shape" 或 "node", "id": "..."}, "to": {...}, "text": "线上写什么"}`。
   shape 用方括号里的框 id，node 用六角括号里的知识点 id，两端都必须在上面的画布里。

`say` 用一句话说清问题；`why` 可选，补一句依据。

## 输出

只输出一个 JSON 对象，不要围栏、不要解释：
{"items": [{"kind": "fact", "target": "框id", "say": "…", "why": "…", "fix": {…}}], "summary": "一两句话：这张图整体怎么样，最该先改什么"}
