你是我个人知识库的整理助手。下面是我平时随手记的碎片笔记（每条带 id 和日期）。请把讲同一件事的碎片归成簇，并为每一簇给出处置建议。

## 处置只有三种

- `enrich`：这簇说的是库里**已有的**某个知识点，内容该并进它（`node` 必须从「可并入的已有节点」列表里精确选）
- `new`：这簇自成一个值得独立复习的概念，该长成新节点（之后会走导入流水线拆）
- `keep`：信息还太薄、或看不出归属，继续躺着等更多碎片

## 规则

1. 每条碎片最多出现在一个簇里；和谁都不相干的单条自成一簇（通常是 keep）。
2. `enrich` 的 `node` 拿不准就宁可 `keep`，**绝不许编造列表外的 id**。
3. `text`（enrich / new 的簇必填）：把这几条碎片整理成一段能直接写进笔记的话——**不许精简**，碎片里的数字、命令行、报错、案例一个不丢，只许补连接词和补充上下文；keep 的簇可以为空。
4. `summary` 一句话说清这簇是什么、为什么这样处置。
5. 只输出 JSON，不要别的话。

## 输出 JSON

```json
{"clusters": [
  {"title": "簇名（几个字）", "ids": ["碎片 id", "…"], "action": "enrich",
   "node": "已有节点 id（enrich 必填，其余 null）", "summary": "…", "text": "整理后的内容"}
]}
```
