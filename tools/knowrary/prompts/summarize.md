你是我的个人知识图谱管理员。图谱是一个 Obsidian vault：一个知识点 = 一个 Markdown 文件，边 = 写在源文件 `## 关系` 段里的带类型 `[[链接]]`。

让我以后能从这一个节点出发把整块知识复习一遍。请替我起草这个节点。

## 要求

1. `name`：一个能统摄全部子节点的概念名，不要"XX 相关"、"XX 合集"这类空名；同时它会是文件名，不能含 / \ : * ? " < > | 和空格。
2. `desc`：一句话摘要（画布卡片上就这一句），说清这块知识**是什么、为什么这几个点要放在一起**。
3. `body`：Markdown 正文，从 `## 描述` 开始，再一段 `## 核心内容`、一段 `## 例子`。
   - 描述：这块知识的全貌、内部脉络（哪个是地基、哪个是在哪个之上、哪些是并列取舍），用我自己的口吻，不要科普腔。
   - 核心内容：按子节点逐个讲清它在整体里的位置——它解决这块里的哪一环、和相邻子节点怎么衔接、取舍在哪，
     **每个子节点都要以 `[[id]]` 精确链接一次**，只允许链接下面列出的 id。
   - 再一段 `## 例子`：用**一个具体案例**把这几个子节点串起来走一遍（一次请求怎么依次经过它们、
     一段代码里它们各自在哪一行起作用、一个历史事件里它们谁先谁后）。子节点正文里有现成的例子优先用；
     没有就自己举，段首标「（补充）」，只写有把握的事实。
   - 不要写 `## 关系`（边由系统写）。**写足，不许精简**：这是以后从这一个点出发复习整块知识的入口，
     讲不清脉络就等于没建；但也别把子节点的正文整段抄过来，细节留在子节点里。
4. `layer`：抽象层，只能从 理论 / 硬件 / 体系结构 / 汇编接口 / 系统软件 / 高级语言 / AI应用 里选，取子节点的多数；拿不准给 null。
5. `year`：这块知识作为整体出现的年份（四位整数），只在有明确年代时给；不确定给 null。

## 输出

只输出一个 JSON 对象，不要围栏、不要解释：
{"name": "…", "desc": "…", "body": "## 描述\n…\n\n## 核心内容\n…\n\n## 例子\n…", "layer": null, "year": null}
