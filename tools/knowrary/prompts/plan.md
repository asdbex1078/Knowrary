## 要求

1. **拆成 2～4 个阶段**，按依赖顺序排：先学的在前，后面的阶段要用到前面的结论。
   每个阶段 **5～10 个知识点**，整份清单不超过 30 个点。
2. **一个知识点 = 一个可以独立复习的概念**，不是一个章节、不是一个任务。
   "读完某本书第三章"不是知识点，"自注意力的 QKV 计算"才是。
3. **上面「这份计划里已经有的点」和「已有的节点」里出现过的概念，必须原样复用那个 id**，
   **也不要另起一个近义的新名字**（`RNN` 和 `RNN与长程依赖`、`BPE分词` 和 `子词分词-BPE`
   这种算同一个点）——否则计划和图谱对不上，同一个知识点我会建两遍。
   这份计划里已经有的点，除非要补充，否则**不用再列一遍**。
4. `id` 同时是将来 Markdown 的文件名：**不能含空格**，也不能含 `/ \ : * ? " < > |`。
   用简短的中文或英文短横线写法，例如 `自注意力`、`positional-encoding`。
5. `why` 写一句话：**为什么这个点在这份计划里、它卡住了什么**。
   不要写"很重要"这种废话，要写它和目标或前一个点的关系。
6. **宁缺勿滥**：目标窄就少拆几个点。凑数出来的点我一样要花时间学。
   **如果上面的时间明显装不下这个目标，照常拆完整的一份**，在 `notes` 里直说要多久才现实——
   够不够我这边会算，你只管把每个点的负荷估准。
7. **`load`（负荷）三档**，按"看懂并且能复述出来"要花多久估：
   `轻` = 一小时内；`中` = 半个下午；`重` = 要动手推导或写代码，得一整天。
   这是我排时间表的唯一依据，别一律填「中」。
8. **`field`（领域）**：这份计划的知识点将来落在哪个顶层领域。
   上面「已有的领域」里有合适的就**原样复用**，没有再起一个新的短名字
   （新名字会成为一个新的目录，所以要短、要稳，例如 `AI-LLM`、`深度学习`）。
