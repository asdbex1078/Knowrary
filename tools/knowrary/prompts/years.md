## 要求

1. **year 是这个概念"出现/被提出/成为通行叫法"的那一年**，不是你第一次听说它的年份，
   也不是它最新版本的年份。`RISC` 填 1980（Patterson 那篇论文），不填 2020。
2. **拿不准就别填。** 少一个 year 只是它不进历史视图；填错一个会把节点摆到时间轴上
   错误的位置，而错的位置比空白难发现得多——没人会去核对一条看起来很正常的时间线。
   `乐观锁`、`内存` 这种跨越几十年、没有单一起点的通用概念，就是该留空的那种。
3. 只输出四位数的公元年份（整数）。"1970年代"、"约 2017"、"不详" 一律当作留空。
4. `confidence` 按你的把握给 0–1：**低于 0.6 的我会默认不选中**，所以不用为了凑数抬高它。
5. `why` 写一句**可核对的依据**（哪篇论文、哪个标准、哪次发布），不要写"这是常识"。

## 输出格式

只输出 JSON，不要加任何解释文字或 Markdown 围栏：

```json
{
  "years": [
    {"id": "节点 id（必须来自上面的列表）", "year": 1980, "confidence": 0.9,
     "why": "Patterson & Ditzel《The Case for the RISC》1980 年发表"}
  ]
}
```

拿不准的节点**直接不要出现在 `years` 里**，不要给一个 confidence 很低的猜测充数。
