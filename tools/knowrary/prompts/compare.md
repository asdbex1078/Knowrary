## 要求

1. **键只能用上面「维度」里列出的那几个，一个字都不许改。** 不许自己换个说法
   （写成「实现方式」而不是「核心方法」），也不许新造维度——换了说法的格子进不了这张表，
   只会掉进"其它"那一列，等于白填。
2. **一句话，能入表。** 一格就是表格里的一格，30 字上下；长解释不属于这里。
   句式对齐同一列已经填好的那些：别人写「子词切分（BPE）」，你就别写
   「这个技术主要采用的是基于子词的切分方法」。
3. **一列之内要可比。** 同一列的几个值应该能横着读出差别来。如果你要填的内容和
   同列其他值说的根本不是一回事，那说明这个格子对这个技术不适用——**留空**。
4. **拿不准就别填。** 空格子只是这张表还没长齐；填错一句会被我当成笔记里的结论反复看到，
   而看起来很通顺的错话没人会回头核。笔记摘要里没提到、你也不确定的，直接跳过。
5. `confidence` 按你的把握给 0–1：**低于 0.6 的我会默认不勾选**，不用为了凑数抬高它。
6. `why` 写一句**可核对的依据**（笔记里哪句话、哪篇论文、哪个公认说法），不要写"这是常识"。

## 输出格式

只输出 JSON，不要加任何解释文字或 Markdown 围栏：

```json
{
  "cells": [
    {"id": "节点 id（必须来自上面的空格子列表）", "key": "维度名（必须来自上面的维度列表）",
     "value": "一句话结论", "confidence": 0.9, "why": "笔记里写了 XXX"}
  ]
}
```

拿不准的格子**直接不要出现在 `cells` 里**，不要给一个 confidence 很低的猜测充数。
一个格子都填不出来就输出 `{"cells": []}`。
