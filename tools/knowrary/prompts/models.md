你在帮我整理一份**谱系目录**里的「{{lineage}}」这张图：把一篇讲某个（或几个）家族迭代史的文章，抽成一个个具体型号 / 版本的结构化条目。

## 规矩

- **只抽文章里写了的。** 没写的字段就不给这个键，不要凭记忆补，也不要猜。数字、日期照文章原样抄（`671B`、`2024-12-26`、`65nm`），不要换算。
- **一个具体型号 / 版本一条**。同时发布的一组可以合成一条；两代写在一行的，能拆就拆成两条，拆不开就合成一条并在名字里保留原写法。
- **名字**：用文章里的正式写法。下面「这张图里已有的」如果有同一个型号，**名字照已有的抄**，别换一种写法。
- **家族**：一个厂商的一条产品线算一个家族。这张图里已有的家族照抄名字。
- **发布**：`YYYY-MM-DD`，只知道月就 `YYYY-MM`，只知道年就 `YYYY`。
- **前代**：同一家族里它直接接替的那一代（文章里明确说了才写）。**基于**：它是在哪个型号的基础上做出来的，可以跨家族。
- **技术**：这一代的核心技术点，每个一项、写短。**下面「图里已有的知识点」里有的，写成 `[[知识点名]]`**；没有的照写文字，不要硬套。
- **亮点**：这一代最值得记住的一两句。**突破**：它解决了什么之前解决不了的问题。都用一两句话，别抄大段。
- **论文**：文章里给了链接才写；「未提供链接」这种话不要当成链接。
- **这张图自己登记的字段**放进 `values`，键用下面列出的中文名；文章里有就一定要抽。
- 其它值得记、但不属于上面这些的，放进 `extra`，键用中文短词。

## 输出

只输出一个 JSON 对象，不要围栏、不要解释：

```
{"families": [{"name": "家族名", "vendor": "厂商", "open": true, "tagline": "一句话说这个家族走的是什么路线",
  "models": [{"name": "型号名", "date": "2024-12-26", "prev": "前一代", "base": [], "tech": ["[[知识点]]", "纯文字技术点"],
    "highlight": "…", "breakthrough": "…", "paper": "https://…", "values": {"<本图字段>": "…"}, "extra": {}}]}]}
```

`open` 是开源 / 开放为 true、闭源为 false、文章没说就不给。
