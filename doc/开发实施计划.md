# Knowrary 开发实施计划

> 目标：逐步交付“Markdown 知识文件 → 图谱结构视图 → Inbox → 手工布局持久化 → 历史视图 → Agent 辅助”的本地系统。
> 原则：先打通可验证闭环，再增加自动化；每个阶段都有独立产物和验收标准。

## 1. 总体架构与职责

```text
Markdown vault → 本地服务（解析、索引、布局、写回、监听） → Vue 3 + X6 前端
```

Markdown 负责知识内容和关系；`.knowrary/layout.json` 负责结构视图；`.knowrary/review-log.json` 负责复习记录；`.knowrary/index.json` 是可重建缓存；ChangeSet 是所有 Markdown 写回的唯一入口。

本地服务用 **Python 3.11+ / FastAPI**，与 `tools/knowrary/knowrary.py` 同栈；前端 Vue 3 + X6 的构建产物提交入库，运行期不需要 Node。LLM 由 `.knowrary/llm.local.json` 配置（多 provider，learn / review 双角色），详见设计文档 3.11。

### 边的可读性（阶段 5 的两项提前做）

72 节点 193 边全画出来是一团麻：结构族 86 条里有 74 条两端同框（嵌套已表达）、26 组平行边完全重叠、全图默认 `router: 'orth'` 绕成迷宫。处理为：

1. 结构族默认不画线（设计文档 3.6），工具条可勾开；
2. 全图默认直线路由，`orth` 只留给阶段 3 的交互式连线；手工调过拐点的边仍按 layout 存的 router 渲染；
3. 同一对节点的多条边按法向错开成分离的弧线；
4. **跨分组边聚合**成「分组 A → 分组 B (n)」一束（粗细随条数），点它展开这对分组之间的明细、再点收起；
5. **悬停 / 选中高亮**：相关边加粗置顶，其余边淡到 0.07。

效果：一屏从 193 条散线降到 60 条组内边 + 16 束跨组边。

### 过程中修掉的三个真 bug（只有真交互才暴露）

1. X6 `embedding.frontOnly` 默认为 true：落点上盖着别的节点时，被拖的节点只解除了旧分组、认不到新分组，归属变成 null。改为 `frontOnly: false` + 自定义 `findParent`（按面积排序命中最内层分组）。
2. 用 `requestAnimationFrame` 放开"初始渲染不写盘"的守卫：后台标签页与无头浏览器里 rAF 不触发，守卫永不放开，用户的拖动被静默丢弃。改为首次真实交互（mousedown / wheel / 点适应窗口）放开，并在入队前与本地镜像比对跳过空写。
3. 程序化重渲染（切关系族、展开聚合束）会重新 `zoomTo` / `translate`，触发视口保存，每次切换都白涨一个 revision。加 `applyingViewport` 标志隔离。

1. **渐显动画不能动 `transform`**：CSS 的 `transform` 会盖掉 SVG 元素自身的 `transform` 属性，加了位移之后 X6 给每个 cell 算好的坐标全被拍回原点，18 个节点叠成一坨。动画只留 `opacity`。

### 补记（同日修订）：加输入框 + 整轮比对诊断

第一版是"心里想一遍 → 看答案 → 自评"，**没有输入框**——试用时立刻暴露问题：不写下来，
自评就是凭印象，而印象最不可靠。改成：

1. **写答案 → 对答案 → 自评三档**（零等待，不调 LLM）。
2. 全部答完后 `POST /api/quiz/diagnose` **整轮一次调用**，逐题给 `missed`（漏掉）/
   `wrong`（记错）/ `suggested_grade` / `comment`。不逐题调：逐题会让每道题卡几秒。
3. **建议档位只许降级**：比我的自评严才提示「下调为 X」，且要点一下才生效；比我松一律不理会。
4. `quiz-log` 增加 `my_answer` / `missed` / `wrong`，诊断本身**只读**，交卷时才一起落盘。

`missed` 与 `wrong` 分开存是这次的关键：漏掉多复习就补上，**记错再考几遍只会把错误记忆焊得更牢**。

实测（故意把 CISC / RISC 的压力归属说反，并漏掉三个 RISC 指令集）：诊断把说反的两处
准确归到 `wrong` 而不是 `missed`，建议档位从我自评的「记得」下调到「忘了」；第二题
类型方向答对但没答指令集，判「模糊」。

### 两个设计决策

1. **批改是自评，不是模型判分。** 自评零延迟零成本，而且"我到底记没记住"只有我自己知道；
   让模型判分只会把一次复习变成一场辩论。
2. **一个节点在同一轮被考到多次，只按最差的一档记一次复习。** 否则一轮答三道题就给这个节点
   记三次，间隔序号凭空跳三级——考得越细，间隔反而被拉得越长。

### 修掉的一个既有 bug（`highlightEdges` 无条件重写边样式）

阶段 9 的 e2e 跑绿之前先撞上两处失败，根因是同一个：`highlightEdges` 退出高亮时
**一律** `removeAttrByPath('line/class')` 并把 `strokeDasharray` 置空。后果两条：

1. 「被激活」边本来自带金色流动虚线（`activationAttrs()` 里的 `class: kg-flow`），
   任何一次高亮复位都把它抹掉，历史视图那条边就不流动了。
2. 更隐蔽的一条：**X6 删属性会让整条边的视图重建，原来的 `<path>` 元素被换掉。**
   这一下如果正好落在 mousedown 与 mouseup 之间，X6 就不再合成 click——
   点边挂不上拐点手柄，而且"第二次点同一条边又好了"，非常像偶发。

改法：每条边把自己的基础样式（`baseClass` / `baseDash` / `baseZ`）记进 `data`，
退出高亮按它还原；并且**值没变就一个字节都不写**（`setLine`），从根上不触发重建。

目标 → 拆出要掌握的点 → 围绕这些点学 → 节点和边因此被建出来。它和复习 / 错题是**两条线**：
线 A 建设（F10），线 B 保鲜（F8 / F9），只在"一个点被建成后自动进入复习队列"这一处交汇。
**所以它不需要图里先有东西，恰恰是用来把图填出来的**，空图也照样跑得起来。

要点：

1. **教练做两件事，LLM 只参与一件。**
   - **制定计划**（目标 → 知识点清单）：生成任务，**必须走 LLM**；输出是提议，进确认面板，人点了才存。
   - **每日调度** `GET /api/coach/today`：确定性排序，**不需要 LLM**。顺序是
     `逾期错题 > 到期复习 > 当前阶段「未建」的点 > 「只有壳」的点 > Inbox`。
     前两项是线 B、中间两项是线 A；空图时前两项为空，清单从第三项起照样排得出来。
2. **`.knowrary/plans.json`**：`points` 里的 id **允许指向图里还不存在的节点**（这正是计划的用途），
   每个点带 `name` / `why`，形状复用导入方案里的 `stubs`。**待建的点不写进 vault**——
   制定一个计划就凭空多出 20 个空壳会污染 check / Inbox / Digest。
   绑 node_id **不绑簇**（簇是视图状态，重排就失效）；**不存 progress**（掌握度现算，存了必漂移）；
   多计划是 map，同一节点可属多个计划。
3. **掌握度五档**：未建 / 只有壳 / 学过 / 已掌握 / 待复习。前两档是这次补上的——
   一个还没写出来的知识点谈不上"学没学"，它是**还没建**。
4. **出题范围可选**（只考到期 / 只考没学过 / 混合）：`QuizRequest.node_ids` 已经接任意集合，
   纯 UI 改动，后端不动。
5. **对话里自动记复习：只许降级不许升级**（已在 F9.4 的整轮诊断里实现同一条规则）。
6. **对话留档用 JSONL，不建 SQLite、不做 embedding**（门槛与理由见 F10.7）。
7. **蒸馏入库复用 `knowrary context / apply` 与 ChangeSet，不重造**；不做"全自动入库"。

**落地情况**

| 块 | 状态 | 产物 |

顺手清掉的一处：`digest` 早先兼管过错题，现在错题只从今日清单出，不留第二个来源。

**实测**（用真实 vault、真实模型）：目标「三个月吃透 Transformer」拆出 4 阶段 29 个点、零 warning；

## 10.7 阶段 11：历史视图增强（主干道 ✅ · 只看一条线 ✅ · 层级钻取 ❌）

方案见**设计文档 F4.6**（那份文档的标题还写着"未实现"，同日一并改掉）。
一句话：**链 ≠ 分类，两种意图得用两种布局。** 看"AI 全景"是分类——现有的
「泳道 + 按分组 / 按层 / 按流派取色」够用，不用改代码；看"NLP 这一条线"是链，要另一种布局。

### 缺口一：主干道布局 ✅（2026-09-15 随 `c7a39d5` 落地，2026-09-22 复核）

- **代码**：`web/src/canvas/timeline.js::longestChain` + `trunkLayout`；
  入口是时间线面板的「主干道」勾选框（`TimelinePanel.vue` → `useHistory.js::hist.trunk`），
  勾上就走 `trunkLayout`，**挑不出链时退回泳道**并在面板上说明，而不是给一张空图。
- **挑主干不是顺着边走一遍**：先按年份给节点定序，再在演化边构成的 DAG 上做一遍
  最长路 DP（`best` / `prev`），所以并行捷径抄不短主轴——实盘里 `MHA → GQA` 正是
  这样一条与 `MHA → MQA → GQA` 并行的捷径，它不会把主干从三站削成两站。
- 不在链上的点**上下交替**挂成旁支，各自跑一遍扫描线（只往一边堆会把图拉得很高）；
  **X 仍锁死年份**，3.8 的前提没破。
- **用例欠账 2026-09-22 补上**：「只看这条演化线」那组 e2e 顺带把主干道按在了断言上
  （自动切主干道、`plan.chain`、泳道标题、`placed.trunk`），unit 里也有一条
  「只看一条线 + 主干道：主轴就是这条线里最长的那串」。`trunkLayout` 现在改坏了测试会红。

### 缺口二：改做「只看这条演化线」✅（2026-09-22），层级钻取仍未做

原设计是全景 → NLP → 注意力**按分组树逐层下钻**。2026-09-22 照着实盘量了一遍，
这条路在当前布局下走不通，于是换了个做法。

**为什么换：钻下去也到不了"注意力这一支"。** 实盘的 layout 是 `layout init --by layer` 铺的——
**顶层按主题、二级按抽象层**，底下没有「注意力机制」这种主题子框。所以钻取只有两层可钻，
而且钻完读图**更差**（名字可读率反而降了，点少了行也少，同一行里挤得更近）：

| 在哪一层 | 泳道怎么分 | 点数 | 年份跨度 | 年宽 | 名字写得出来 |
| --- | --- | --- | --- | --- | --- |
| 全景（默认） | 按 field，2 条道 | 76 | 1936–2024 | 32px/年 | 82% |
| 钻进「AI」 | 直接子分组 = 6 条抽象层道 | 34 | 1943–2024 | 35px/年 | 56% |
| 再钻「AI／AI应用」 | 没有下层了，1 条直属道 | 15 | 1965–2024 | 47px/年 | 47% |

`MHA / MQA / GQA / MLA / Transformer / BERT / ViT / Whisper` 全在同一个 `AI应用` 框里，
钻到底就是这 15 个点挤一条道——**还是散点加连线**。

**所以做的是「只看这条演化线」**：双击历史图上的圆点，可见集合按**血缘**裁到
「祖先 + 后代 + 直接旁系」，自动切主干道，Esc 退出。三条判断：

1. **口径是血缘，不是连通块。** 只走 `演化为` / `扩展为` / `修订`（`源自` 反向折算），
   **`被激活` 不算**——它是跨代点燃，算进来一条线会顺着 `CUDA 被激活 Transformer`
   窜到硬件那边去，整族都被拉进来等于没筛。
2. **必须带直接旁系。** 只取祖先后代的话，从「注意力机制」出发会漏掉 `MHA`
   （`MQA` 的上游、却不是根的祖先）和 `MLA`（`MQA` 的同父兄弟）——而这两个恰恰是
   "注意力这一支"的主要内容。旁系按三条收，都只到一跳：直接上下游、同父兄弟、同子汇流。
   实测：注意力机制 → 主线 9 + 旁系 2；ISA → 主线 5（正好是最长那条链）+ 旁系 `CISC` / `VAX`。
3. **旁系画淡不隐藏**（`.kg-kin`，悬停恢复）：它在图上是参照，不是内容。

代码：`timeline.js::lineageOf` + `buildTimeline({ lineage })`（裁在算比例尺**之前**，
否则年宽还是按全图跨度算的）、`useHistory::enterLineage / exitLineage`、
`App.vue` 的 `node:dblclick` 与 Esc、`TimelinePanel` 上的状态块与退出口。
用例：unit 5 条（血缘口径 / 被激活不算 / 源自反向 / 裁完重标定 / 主干道挑最长），
e2e 8 条（双击筛出三个点、甲退出视野、旁系带 kg-kin、自动主干道、横幅、面板、Esc 还原、不写盘）。

**层级钻取本身仍然没做**，也不该急着做：历史视图的泳道条 `kg-lane`（`render.js:27`）
还是没有点击处理。**它的前置也变成了数据**——要么在 `AI应用` 里再开几个主题子框，
要么继续用「只看这条线」，那才是"看一支"真正要的东西。

## 10.8 阶段 12：项目化重构 ✅（五期 2026-09-16 全部完成）

### ② 导入产物三分 ✅

一篇笔记的方案 JSON（`prompts/article.md`）翻成三种产物（`core/importing.py::translate`）：

| 产物 | 落到哪 | 怎么写 |
| --- | --- | --- |
| 新建节点 | `create_node` + `add_edge` | 与画布右键建点同一条 `/api/changes` 通道 |
| 补充老节点（`enrich`，旧名 `merge_into` 仍认） | `append_body` | **只追加**，开头一行 `> 补充自《来源》（日期）：why`，不碰老正文 |
| 待审边 | `.knowrary/pending.json`（第五份契约） | 连到**已有节点**且 `confidence < 0.8` 的边不进 md；新↔新直接写 |

- CLI `knowrary apply` 和 `POST /api/import` 共用这一份翻译；dry-run 给每个文件的 diff（新文件全文）。
- 落盘：`core.commit` 自动备份 → 记 pending → 方案与变更集存档 `.knowrary/imports/` → 索引缓存作废。
- 契约：`server/contracts.py::ImportRequest / ImportResult / PendingEdge`；`core/pending.py` 当时只有
  load / add（按 `源->目标#类型` 去重）/ remove 三个动作，审核入口留给后续阶段——**2026-09-29 补上了**，
  见 §10 表后那段「待审边的审核入口」。在那之前进了待审的边只进不出：没有任何地方读 `pending.json`。
- 边界：正文里带 `## 关系` 段被截掉并警告；已存在的 id 不覆盖、提醒改 enrich；正文链到不存在的 id 自动补 stub；
  旧方案没 `confidence` 字段按 1.0 处理，不会因此全进待审。

### ③ 导入入口进 Web ✅

- **入口**：活动栏「导入」面板（项目 / 全局两个作用域都有），不放进对话——一篇长文会把对话历史吃光，
  拆解也该是一次专门的 learn 角色调用。文章三种来路：粘贴 / 仓库里的 md·txt（`GET /api/import/sources`，
  节点目录与代码目录之外的全部；`GET /api/import/source?path=` 读，越界与非素材目录一律 422）/ 本地文件（浏览器里读，不上传）。
- **`POST /api/import/propose`**：一次 LLM 出方案，顺手 dry-run 把 diff 带回来。三级匹配在服务端算完：
  · **认领幽灵**——提示词多一段"当前项目里还没建的点"（`core.article` 拼装，CLI 同一份），模型写 `claims` 的节点 id 直接换成清单 id，
    连带改所有指向它的关系和正文链接（`core.rename_in_plan`）；
  · **近似撞名**——没认领但名字和某个清单点很像（子串或相似度 ≥ 0.6），卡上给「改用清单里的 id」一键；
  · **孤立**——按方案里的连通块算：整块没有一条边碰到已有节点、也没认领的才报，模型顺手给 `suggest_home`（只是建议，不自动建）。
- **审核卡**照对话变更卡的样子：按节点一行（id、摘要可改、认领标记、正文可展开改）、补充老节点清单、
  **待审边可勾选直写**（`promote`，按 `源->目标#类型` 的 key 抬到置信度 1）、提醒、每个文件的 diff；「重算 diff」和「写入」都打 `/api/import`，
  `renames` / `promote` 由服务端改方案再翻译，前端不自己拼改写。**先提升再改名**：key 是按卡上显示的 id 拼的。
- **落位**：项目下认领的点原地从幽灵转草稿，其余新点停右下角（`App.vue::parkNodes`，和「放到右下角」同一处），全部补进清单；
  全局走 `/api/place` 按邻居投票，放不下的进 Inbox。补充过的老节点只刷索引，位置不动。

### ④ 严格串行的批量队列 ✅

- 全在导入面板里（`ImportPanel.vue`），服务端没有新东西：队列是前端的，一次只打一个 `propose`。
- 入队三条路：仓库文件列表勾多篇「加入队列」/ 本地文件一次选多个 / 粘贴一篇「加入队列」。同路径或同名未完成的不重复入队。
- 推进纪律：`waiting → proposing → review → done | skipped | failed`。**上一篇点了「写入」或「跳过」之后才起下一篇**——
  后一篇拆解时服务端索引已含前一篇刚建的节点，能连上、能看出重复。拆解失败停在那一篇等人「重试 / 跳过」，不自动往下烧钱。
- 写入后推进放在 `finally` 之后：`runNext` 的守卫看 `working`，写入还没收尾就起下一篇会被挡回去（改的时候踩过）。
- 队列只活在内存里，刷新即清；已写入的文件不受影响。审核卡头上标「第 k/n 篇 · 名字」，队列区在来源区之外常显。

### ⑤ Inbox 增强 ✅

- **零边标记**：degree 为 0 的条目把「N 关系」换成警示 chip「0 关系 · 让 AI 建议」，点了直接选中它、开检查器、要一轮 `/api/suggest`
  （Inbox 里的点不在画布上，`gotoNode` 跳不过去，所以单独走 `App.vue::suggestForInbox`）。放上去就是孤点，投票也算不出分组——先补边。
- **一键建域框**：`InboxItem.field_group_missing` = 有 field、判不出分组、且画布上没有同名顶层框（判不出分组的根因）。
  按钮「建「X」域框并放入」→ `POST /api/place` 带 `create_field_group: true`：服务端 `core.plan_field_group` 在整张图最下面开一个同名顶层框
  （加法，不动已有内容；两行四列的量，放满了 place_or_grow 自己往下长；泳道留给 regroup 的 create_lane），再把节点放进去；
  同一批第二个同领域的复用那个框。`PlaceResult.created_groups` 单列，不混进 grown_groups。
- **孤立提议**：不另调模型——导入落盘时把方案里的 `suggest_home` 记进 `pending.json` 的 `homes`（只记这次真建出来、又被模型点名孤立的 id），
  Inbox 条目上显示「建议归到领域 / 项目「X」——why（来自《文章》）」；放上画布后条目消失，建议自然不显示。同一批节点再导会覆盖旧建议。

### ⑥ 概括节点菜单 ✅

用户定的：分组框（排版）和"概括节点 + 包含边"（知识）**都要**，正文由模型先起草、人再调（选了 B）。

- **两个入口**：分组菜单「把框里的 N 个点概括成一个节点…」（≥2 个点且框还没绑总览）；框选（Shift 拖框 / 点选）≥2 个点后右键其中一个
  「把选中的 N 个点概括为一个节点…」。菜单上下文多了 `selectedIds`（`graph.getSelectedCells` 过滤 kg-node）。
- **`POST /api/summarize`**（`server/summarize.py`，提示词 `prompts/summarize.md`）：learn 角色一次调用，输入子节点的摘要、正文节选（500 字）
  和已有关系，输出 name / desc / body / layer / year；回答里混进 `## 关系` 截掉；最多 40 个点；不在索引里的 id 被过滤，剩不到两个 422。
- **新建对话框**预填草稿：名字 / 摘要 / 正文都挂「AI 建议」标记，改过就消失（和 layer / year 同一套做法）；对话框显示「包含：…」。
  **起草失败也照样开对话框**，只是正文留空——概括是人的判断，模型垫不出稿不该挡着人建节点。
- **写入一次到位**：同一份 ChangeSet 里 `create_node`（带 body）+ 每个子节点一条 `add_edge 包含`（写回通道支持给刚建的节点挂边）。
  框菜单进来的建完绑成该框的总览（`bindDoc`）；框选进来的可勾「顺手建一个框把它们圈起来」：按子节点包围盒建框、把它们归进去、新点落在框底一行、绑总览。
