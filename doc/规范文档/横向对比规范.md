# Knowrary 横向对比规范

> 版本：v2（2026-09-20）
> 适用范围：横向对比相关的数据组织与视图契约。节点基础元数据、关系、学习计划见
> 《Markdown文档规范》与《第二版设计文档》，本文只补对比这一块。

## 0. v1 → v2 改了什么

| v1 | v2 | 为什么 |
| --- | --- | --- |
| `groups/<id>.md`、`tags/<id>.md` 两个新目录 | 只有 `fields/对比组/<id>.md` | `mdio.py:15` 的 `NODE_DIRS` 只扫 `nodes` / `fields`，新目录不会被解析，`[[compare-x]]` 反而变成"被引用但没建"的 stub |
| `members: [a, b]` frontmatter 数组 | `- 包含:: [[a]]` 关系边 | `rename.py` 明确不改 frontmatter，数组会在改名时悄悄悬空；边则自动跟随，还能被 `check` 校验 |
| `category` 新字段 | 删掉，用已有的 `field` / `tags` | 单值、和 `field`/`tags` 语义重叠，且示例里按 name 写、按 id 引，口径不定 |
| 独立的标签文档 `tags/` | 删掉 | 它的三件事（定义类别 / 列成员 / 声明维度）分别已由 `fields/` 领域总览、`包含` 边、对比组的 `dimensions` 承担 |
| `## 关联关系` | `## 关系` | 解析器只认 `## 关系`（`mdio.py:25`），写别的名字是**静默丢边** |
| 一个 `## 对比项` 同时装属性和差异 | 拆成 `## 速查`（属性，入表）+ `## 对比项`（差异，对齐 `对比` 边） | v1 的键空间自相矛盾：§3 的键是"与RNN对比"，§6 却按"年份/核心方法"取值，表格必然全空 |
| `年份` 维度写进正文 | 读 frontmatter 的 `year` | `year` 是历史视图的开关（规范 §3），正文再写一份就是双源 |
| 新增 `get_compare_anchors` / `get_compare_section` 工具 | 用现成的 `read_node(outline / section)` | `server/chat.py:200` 已经实现，`core/sections.py` 还做了标点归一化 |
| 维度别名映射表 | 删掉 | 写入时用 `dimensions` 当枚举约束；写歪了由残差列当场暴露，手动改一下即可 |
| 对比卡片在全局画布上双击展开 + 临时虚线 | 对比组**不上全局画布**，各有一张自己的画布 | 全局图已经够复杂了；临时虚线还和"对比是一条真边"打架 |

## 1. 三个存放位置

```
fields/对比组/<id>.md           对比组文档（成员、维度、结论）
nodes/**/<节点>.md              节点里的 ## 速查（属性）与 ## 对比项（差异）
.knowrary/layouts/<id>.json     这个对比组自己的画布（复用 LayoutDoc 契约）
```

**没有新的机器数据契约。** 对比组是 `fields/` 下的普通节点，走同一套解析、索引、改名、备份；
对比画布复用项目画布那份 `LayoutDoc`（`server/paths.py:33`）。

## 2. 对比组文档

### 2.1 路径与 frontmatter

`fields/对比组/compare-分词.md`

```yaml
---
id: compare-分词
name: 分词技术对比
field: AI
type: 对比组
dimensions: [核心方法, 适用场景, 优点, 缺点]
desc: 从统计方法到子词切分的分词技术横向对比
---
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 否 | 缺省取文件名。约定以 `compare-` 开头——它和知识节点共用一个 id 命名空间（`load_vault` 撞 id 直接报错） |
| `name` | 是 | 显示名 |
| `field` | 是 | 顶层领域。**必填是全局规则**（`parser.py:26` 的 `REQUIRED_FIELDS`），不填 `knowrary check` 每份报一条错 |
| `type` | 是 | 固定 `对比组`。值用中文，跟已有的 `领域总览` / `模型架构` 一个风格 |
| `dimensions` | 是 | 表格的列，决定取数的键。需要加进 `index.py:25` 的 `NODE_FM_FIELDS` 才能到前端 |
| `desc` | 是 | 一句话 |

### 2.2 正文

```markdown
# 分词技术对比

## 概述
分词是 NLP 和搜索的基础环节。从统计方法到子词切分，技术路线差异很大。

## 维度说明
- **核心方法**：主要算法或工具
- **适用场景**：最适合的应用领域

## 结论
n-gram 是统计基础，jieba 是中文工程化标杆，tokenizer 是子词切分的代表。
它们在"粒度"和"场景"上各有取舍。

## 关系
- 包含:: [[n-gram]]
- 包含:: [[jieba]]
- 包含:: [[tokenizer]]
```

**成员就是 `包含` 边**（结构族，`relation-types.json`）。换来四件事：改名自动跟随；
`check` 自动校验目标存在；`degree > 0` 所以不会被当成孤点；全局图上（如果哪天想看）
它和成员是连着的，不用另造一种"同组"的虚线。

**成员还没建出来**：按规范 §6 的老办法建一个 stub 文件（`status: stub`，desc 待补充）。
不建的话，`包含` 边会和全库任何悬空引用一样报 `unknown_target` 错误——这一条是全局口径，
不给对比组开特例。画布上 stub 就是「只有壳」（学的小方块是红的），不需要另造一种幽灵：
幽灵是项目画布的概念，那边的点存在 `projects.json` 里，本来就允许指向图里没有的东西；
md 里的边不允许。

## 3. 节点里的两节

**位置硬约束：两节都必须写在 `## 关系` 之前。** `parser.py:96` 把 `## 关系` 之后的内容
切成 `rel_tail`，而 `server/quiz.py:67` 的 `_read_body` 只取关系段之前那一段——写在后面，
出题和摘要都看不见。

### 3.1 `## 速查`：属性，可入表

```markdown
## 速查
- 核心方法:: 子词切分（BPE）
- 适用场景:: 大模型输入预处理
- 优点:: 无 OOV、跨语言通用
- 缺点:: 切出来的片段不对应语义词
```

- 用 `::` 而不是单冒号：规范 §1.4 要求兼容 Dataview 内联字段，而它不会被关系解析器
  误读（解析器只切 `## 关系` 那一段）。
- **一行一个键，值是一句话结论。** 长解释放正文别处。
- **不写 frontmatter 已有的东西。** `年份` / `参数量` / `抽象层` 分别读 `year` / `params` / `layer`，
  在速查里再写一份就是双源，必然不一致，而且错的 `year` 比空的 `year` 难发现。

### 3.2 `## 对比项`：和某个具体对象的差异

```markdown
## 对比项

### 与 [[jieba]]
- 粒度: 子词 vs 词
- 依赖: 纯数据驱动 vs 依赖词典
```

- 每个 `###` 的目标**必须有一条真实存在的 `对比` 边**。一句话结论写在边的说明上
  （`- 对比:: [[jieba]] — 子词 vs 词，不依赖词典`），这一节只放展开不下的长版本。
  否则图上看不见这条对比，而"看得见"正是这个产品的全部。
- 只有两三句话能说清的差异，**只写边、不写这一节**。

这两节都会自动进出题轮换（`server/quiz.py:52` 的 `SKIP_SECTIONS` 没有排除它们）：
速查出回忆题，对比项出辨析题。这是想要的。

## 4. 取数：三条规则，没有别名表

```
某成员在某维度上的值 =
    1) 这个维度映射到 frontmatter 字段吗（年份→year、参数量→params、抽象层→layer）→ 读它
    2) 否则看 `## 速查` 里有没有同名键 → 读它
    3) 都没有 → null，表格留空，不报错
```

**不做别名归一化。** 理由：映射表是在猜"你可能会怎么写"，维护成本永远在；而写歪了的键
不会消失，它会出现在下面的残差列里，看一眼就能改。

**写入端要约束。** 让模型填 `## 速查` 时，把这个组的 `dimensions` 当枚举硬塞进 prompt：
"只能用这些键；这个节点真没有的就留空，不要编，也不要自己换个说法"。

### 4.1 取数层返回什么

`core.compare_table(vault, index, group_id)`（不是对比组就返回 `None`）：

```python
{
  "id": "compare-分词", "name": "分词技术对比", "field": "AI", "desc": "…",
  "columns": ["年份", "核心方法", "适用场景"],        # = dimensions
  "rows": [
    {"id": "jieba", "name": "jieba", "built": True, "stub": False,
     "cells": {"年份":     {"value": "2012", "source": "frontmatter", "field": "year"},
               "核心方法": {"value": "词典 + HMM", "source": "速查"},
               "适用场景": {"value": None, "source": None}},
     "extra": {"实现方式": "双数组 Trie"}},           # 残差列
  ],
  "uniform": ["核心方法"],       # 整列取值相同，默认收起
  "promote": [{"key": "实现方式", "count": 2, "members": ["tokenizer", "jieba"]}],
  "cells": 6, "gaps": 1,
}
```

三件事在这一层定死了，第 3 步照着渲染就行：

- **行序按对比组 md 里 `- 包含::` 的书写顺序**，不是 id 字典序。索引里的边排过序，拿它当行序
  读出来就是字典序，而你写下的那个顺序（通常是年代或演进次序）才是读表的顺序。想调整行序
  就去 md 里挪那几行。反着写的 `- 属于:: [[对比组]]` 也算成员，排在后面。
- **每格带 `source`**：`frontmatter` 的格子要走 `update_frontmatter` 改，`速查` 的格子走
  `set_fact` 改一行。编辑入口按它分流，不能一律整段替换正文。
- **还没写的成员照样占一行**（`built` / `stub` 标出来）。"这个还没写"本身就是表里的信息，
  抽掉它这张表就在骗人。

`core.compare_gaps(vault, index)` 给欠账：空格子占比 > 50% 的组。它已经挂进
`build_digest` 的 `compare_gaps` / `counts.compare_gaps`，`/api/digest` 直接就能拿到。

### 4.2 残差列（表格最后一列）

**定义：这个成员 `## 速查` 里所有没被 `dimensions` 认领的键，原样列出来。**

不是"让模型另外总结的独特点"——那是新生成的内容，你没法验证。残差是可验证的余数，
一列干两件事：

- 只有它有这条 → **真·独特点**，这正是对比表最值钱的部分；
- `实现方式` 本该写成 `核心方法` → **措辞跑偏了**，明晃晃躺在残差列里。

这一点是必须的：如果只按 `dimensions` 取值，写错名的那格显示为**空**，你看到的是
"这篇没写"，看不出"写了但名字不对"。空格子和写错名必须能分开。

**升维规则**（替掉别名表的那一半）：残差里同一个键出现在 **≥2 个成员**上 → 表头提示
「这看着是个维度，升成一列？」，点一下写进对比组的 `dimensions`，表格重算。
只出现 1 次的就是独特点，留在残差列。这个动作只改对比组文档，不动任何成员的 md。

## 5. 视图：对比组各有一张自己的画布

### 5.1 为什么不上全局图

全局图已经背着 94 个点、15 个分组框、跨组桥聚合、LOD 折叠。对比组是**聚合视角**，
不是知识点，塞进去只会让主图更难读。所以：

**对比组不进全局画布、不进 Inbox、不算孤点。**

实现口径（**九处**，都是加一个跳过。原以为四处，扫了一遍才发现好几张表各写了一份自己的过滤）：

| 位置 | 改法 |
| --- | --- |
| `index.py` | `type` 属于聚合类（`对比组` / `领域总览`）时标 `aggregate: true`，下游只看这个布尔值 |
| `placement.inbox_ids` | 跳过，否则每建一个对比组，Inbox 就多一条"该放哪" |
| `digest.lonely` | 跳过。**顺手修一个已有的噪音**：`fields/计算机系统.md`（`领域总览`、degree 0）一直挂在孤点列表第一屏 |
| `digest.no_year` | 跳过：一张对比表没有"诞生年份" |
| `digest._pairs` | 跳过：`分词技术对比` 和 `分词` 字面重合度很高，但那是"表和它的表头"，提一次就是一次噪音 |
| `review.due_nodes` | 跳过：要背的是成员，不是那张表 |
| `coach._lonely_items` | 今日清单自己抄了一份孤点过滤 |
| `coach.quiz_pools` | 出题范围 |
| `server/years.missing` | 补 year 面板在服务端另有一份 |
| `layout.bucket_nodes` / `bucket_by_layer` | 用**更窄的** `OFF_CANVAS_TYPES`（只有对比组）——领域总览是一个领域的入口，摆在自己那个域框里是有用的，实盘上就摆着 |

搜索、`read_node`、改名、备份照常——它仍然是知识层的一部分，只是不在主图上占位置。

### 5.2 目录入口

左侧栏**全局工具**那一组（项目管理 / Inbox / 欠账 / 日历 旁边）加一项「对比」。
点开是抽屉里的目录树，和时间线选择器同一个形态（`Drawer` 组件现成）：

```
AI
  分词技术对比          5 个成员 · 4 列 · 3 格空
  注意力变体对比        6 个成员 · 5 列
计算机系统
  编译执行策略对比      3 个成员 · 4 列
```

**这份目录不是新数据**：从 `index.json` 里按 `type == "对比组"` 过滤，按 `field` 分层。
改名、删除自动跟随。

### 5.3 对比画布

点目录里一条 → 进这个组自己的画布，全局图完全不受影响。

- **存储**：`.knowrary/layouts/<对比组id>.json`，复用 `LayoutDoc`（同一份契约，同一套
  乐观并发 + 备份）。`_layout_target` 现在返回 `(文件名, builder)`：id 先过一道形状校验
  （`core.RE_ID_OK`，允许中文、不许空白和路径分隔符、不许以 `.` 开头），再确认它**真的是**
  index 里的一个项目或对比组——后面这一步才是真闸，查无此 id 的名字根本进不来。
- **上半屏是图**：成员按 md 里的书写顺序铺成网格（`core.build_compare_layout`），还没建出来的
  画成幽灵占位。这块画布**可写**，拖动写的是它自己那份文件。
- **下半屏是表**：`.stage` 在对比模式下改成纵向两行。**不把表绝对定位盖在画布上**——
  盖上去的话 `zoomToFit` 仍按整块高度算，成员会被摆到表底下看不见。
- **换组 = 换一份 layout**：撤销栈必须清掉。跨画布撤销会把补丁打到错的文件上，
  这是多份 layout 带来的真风险，和切项目画布同一条规矩。
- 「对比」这个工具在对比模式下**留在侧栏**（不像谱系那样整条收起）：进了某个组还能
  直接跳去另一个组，不用先退回全局图。
- **点表格某行跳到那个节点**。图 ↔ 表的双向高亮联动还没做。


### 5.4 表格

- **长文本截断，点击展开。**
- **列可选**：勾选要显示的列。这是**视图偏好，不回写 md**——`dimensions` 是"这个组按
  哪些维度对比"的真相，"我这次只想看 3 列"不是。混在一起的话看一眼表就改一次 md，
  git 里全是噪音。存 localStorage，按对比组 id 分开记（`Drawer` 的 `storage-key` 是现成用法）。
- **整列一致自动收起**：某一列所有成员取值相同 → 默认收起，标一句「8 项一致」，点开能看。
  对比表的信息量全在差异上，20 行 × 8 列时这一条比手动勾列更省事。
- **单元格可编辑**：双击改一格 → 回车写回（`set_fact`，自动备份）。空值 = 删掉这一行，
  表格里清空一格本意就是"这条我没有"。**frontmatter 那几列在表里只读**——它们的真相在
  frontmatter，从正文写第二份就是双源；双击它们会跳到那个节点。

### 5.5 编辑单元格：用精准变更，不要整段替换

改一格**不能**走 `update_body`。`server/chat.py:722` 已经把这个风险写死了：整段替换
必须先读到全文，长笔记会被截断，替换等于把没看见的部分永久删掉。

新增一种精准变更 `set_fact(node, key, value)`：只重写 `## 速查` 里那一行（没有就追加），
走 writer 现成的链路——digest 比对（Obsidian 动过就拒绝覆盖，`parser.py:19`）、
预览 diff、自动备份到 `.knowrary/backup/`。

### 5.6 补空格子

表头一个「补这 N 格」：**一次调用问完整张表的空格子**（不是每个成员一次——
5 成员 × 4 列逐个问就是 20 次）。这和 README 里 year 补全那条是同一个口径。
一次给整张表还有个逐格问拿不到的好处：**模型能横着看**，同一列已经填好的那几格就是口径。

产出走卡片：每格标着把握，低于 0.6 的默认不勾，**写入前可以改**（输入框直接改），
确认后一批 `set_fact` 写回（所以备份只有一份）。三道闸都在：

- 只认**我们问过的那些格子**——模型顺手填一个没问的格、或自造一个维度名，一律丢掉；
  自造的维度名根本进不了这张表，放过去只会变成残差列里的垃圾。
- 模型说"拿不准"而跳过的格子**如实列出来**，别让人以为补齐了。
- 写回走 `/api/changes`，diff 预览、备份、写前指纹校验一样不少。

## 6. 校验（加进 `knowrary check` / 欠账）

已实现（`core/index.py` 的 `_check_compare`，跟着 `build_index` 一起跑，所以
`knowrary index` 和 `knowrary check` 都管）：

| 诊断码 | 级别 | 说明 |
| --- | --- | --- |
| `compare_too_few_members` | error | 对比组的 `包含` 边 < 2，一个成员的对比组没有意义 |
| `compare_no_dimensions` | error | `dimensions` 缺失或全空，表格没有列 |
| `compare_dup_dimension` | warn | `dimensions` 里有重复项 |
| `compare_section_without_edge` | warn | `## 对比项` 的 `###` 对不上一条 `对比` 边＝图上看不见这条对比。对称边两头写哪边都算数 |
| `compare_section_no_link` | warn | `## 对比项` 的小节标题里没写 `[[目标]]`，对不上任何节点 |
| `facts_shadows_frontmatter` | warn | `## 速查` 里写了 `年份` / `参数量` / `抽象层`，和 frontmatter 双源 |
| `facts_bad_syntax` | warn | `## 速查` 里写成单冒号，取数时整行被忽略 |
| `facts_duplicate_key` | warn | 同一个键写了不止一次，只会用第一条 |
| `facts_after_relations` | warn | `## 速查` / `## 对比项` 写在了 `## 关系` **后面**。这是**静默失效**：关系段之后的正文被切成 `rel_tail`，取数、出题、摘要读的都是关系段之前那一段。追加到文件末尾是最顺手的写法，也正是会掉进这个坑的写法，所以必须有人喊一声。`set_fact` 遇到这种也会拒绝——在前面再建一节就成了两个 `## 速查`，旧的那些格子会像从没写过一样消失 |
| `unknown_target` | error | `包含` 的目标不存在。**全局口径，不开特例**——先建 stub |
