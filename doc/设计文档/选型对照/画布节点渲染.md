# 选型对照：画布节点用不用框架组件

> **结论：不用。节点形状是裸 SVG markup，框架组件只用于面板类 UI。**
> 冲突：**约束 3**（上界由代码封顶）——每个节点一个组件实例 + 一个 `foreignObject`，
> 上界会跟着节点数线性涨。
> 触发线：无。性能守则是写死的，见 §4。
> 代码：`web/src/canvas/`（`Graph.registerNode('kg-node', ...)`、LOD、分组折叠）。
> 判据与总表：《[选型判据](选型判据.md)》。相关：《第二版设计文档》§3.6。

这一条特别之处在于：**第一版就是按"自定义 Vue/React 组件节点"设计的，第二版把它推翻了。**
所以它不是"没试过所以不用"，是"想清楚了上界在哪"。

---

## 1. 现在是什么

```javascript
Graph.registerNode('kg-node', {
  inherit: 'rect', width: 160, height: 60,
  markup: [{ tagName: 'rect', selector: 'body' },
           { tagName: 'text', selector: 'title' },
           { tagName: 'text', selector: 'desc' }],
  attrs: { body:  { rx: 6, ry: 6, fill: '#fff', stroke: '#999' },
           title: { refX: 10, refY: 20, fontSize: 13, fontWeight: 600 },
           desc:  { refX: 10, refY: 40, fontSize: 11, fill: '#666',
                    textWrap: { width: -20, ellipsis: true } } }
})
```

三个 SVG 元素，没了。边按 5 个关系族注册 5 种样式（颜色 / 线宽 / 虚线 / 箭头），
结构族干脆不画线——它表现为嵌套。

---

## 2. 冲突点：上界跟着节点数涨

**用框架组件节点**意味着每个节点：

- 一个 Vue/React 组件实例（响应式依赖、生命周期、diff）
- 一个 `foreignObject`（SVG 里嵌 HTML，浏览器对它的渲染优化最差）

于是"能画多少个节点"取决于"组件有多重"，而组件是会长胖的——
今天加个 badge，明天加个 tooltip，上界就悄悄降一截。**这正是约束 3 要防的事**：
上界应该由代码显式封顶，而不是由"这次加了什么"决定。

**裸 markup 的上界是可以算的**：3 个元素 × 可见节点数，就这么多。

---

## 3. 框架用在哪

Vue 3 **是**依赖（见《[被接受的依赖](被接受的依赖.md)》），只是分工划清楚了：

| 用 Vue | 不用 Vue |
|---|---|
| 左侧栏、抽屉、面板、托盘、Digest | 画布上的节点形状 |
| 卡片（变更卡 / 项目卡 / 拆点卡 / 清单卡） | 边 |
| 对话区 | 分组框与簇卡片 |

**判据是"这个东西会不会被画几千个"。** 面板只有一个，节点有几千个。

---

## 4. 配套的性能守则（写死，不是建议）

1. 视口可见元素常规目标 **300～600**，超过 **1500** 必须由 LOD 自动折叠；
2. 节点 markup **≤ 3 个 SVG 元素**；**不用 `foreignObject`**；
3. 拖拽过程中**不写盘**，松手后节流写 layout；
4. 边 label 只在 `zoom > 0.8` 时渲染；
5. 全图搜索、度数统计等在**服务端或 Web Worker** 做，不遍历 X6 模型。

配套的还有**投影模型**：X6 的数据模型里只放当前可见的元素
（展开分组的直接子元素 + 折叠分组的簇卡片 + 两端可见的边），折叠掉的子树不进模型。
**这样无论 vault 多大，X6 模型规模始终受可见元素预算约束**——
这才是约束 3 在前端这一侧的完整形态：不是"节点画得轻"，是"根本不把它放进模型"。

---

## 5. 代价

- **节点长什么样，改起来比写组件麻烦。** `refX` / `refY` 手算位置，没有 flex。
  「学 / 考」两个小方块、stub 的虚线边框、金点，都是往 `markup` 里加 selector 加 attrs。
- **没有组件复用。** 节点样式和面板样式是两套写法，同一个"红色代表没掌握"要写两遍。
- **文本截断靠 X6 的 `textWrap`**，不如 CSS 灵活。

> 这三条都是**用编辑体验换渲染上界**。值不值取决于节点数——
> 95 个的时候看着不值，但这个产品的立意是"整个知识体系"，几千个是要奔着去的。
