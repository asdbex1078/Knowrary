# 选型对照：测试框架

> **结论：不用 pytest 等第三方框架。一个 `@case` 装饰器收集用例，三处各一份。**
> 冲突：**0 条**——不冲任何约束，纯粹是收益不够。
> 触发线：需要 fixture 作用域管理、参数化矩阵，或者用例多到必须并行跑。
> 代码：`tools/knowrary/tests/run.py`（核心库）、`server/tests/run.py`（服务端）、
> `web/tests/unit.mjs`（前端纯函数）、`web/tests/e2e_canvas.py`（画布 e2e）。
> 判据与总表：《[选型判据](选型判据.md)》。

---

## 1. 现在是什么

**全部的"框架"就是这五行**（`server/tests/run.py`）：

```python
CASES: list = []

def case(fn):
    CASES.append(fn)
    return fn
```

加一个 `main()`：按关键字过滤、跑、打 `✓ / ✗`、最后一行 `N/M 通过`、失败就 `exit(1)`。

```python
def main() -> None:
    keyword = sys.argv[1] if len(sys.argv) > 1 else ""
    picked = [c for c in CASES if keyword in c.__name__]
    ...
```

规模：**301 个用例**（服务端 208 + 核心库 93），另有前端 23 条纯函数用例与 232 条画布 e2e。

---

## 2. 对照：pytest 会带来什么

| pytest 给的 | 这里用不用得上 |
|---|---|
| **用例收集**（`test_*` 自动发现） | 五行就够。而且显式 `@case` 比约定发现更好读：翻到文件末尾就知道有哪些用例 |
| **fixture 与作用域** | 每个用例自己 `make_vault()` 搭一个临时 vault，**故意不共享**——共享状态的测试是这类项目最容易出的那种假绿 |
| **参数化** | 现在没有一处需要参数矩阵。真需要时 `for` 循环 + `assert ..., (入参, 实际值)` 就是参数化 |
| **断言重写**（失败时打印表达式） | 用例自己带上下文：`assert seen[1]["extra"] == "--resume", (seen[1], "第二步没续上 = 又在重发全文")` |
| **插件生态**（覆盖率、并行） | 覆盖率没用过；并行用不上，全量跑是秒级 |
| **`conftest.py` 层级配置** | 三处 runner 各自独立，不需要层级 |

**换来的是**：开发依赖少一个（现在只有 `httpx2` + `pyflakes`），
以及 `python server/tests/run.py [关键字]` 这种零配置的跑法——
**不装任何东西、拿到仓库就能跑**，这和"开源之后别人怎么用"是同一条线。

---

## 3. 三处 runner，同一套写法

写法在三处是刻意对齐的（`web/tests/unit.mjs` 的注释里明写着"和 `tools/knowrary/tests/run.py`、
`server/tests/run.py` 一样"）：

**一个 case 一个函数，名字就是断言本身，失败时把实际值打出来。**

```
tools/knowrary/tests/run.py   核心库：临时 vault → build_index → 断言节点/边/诊断/契约
server/tests/run.py           服务端：临时 vault → TestClient 打真实路由
web/tests/unit.mjs            前端：只跑 canvas/ 下不碰 DOM 的纯函数
web/tests/e2e_canvas.py       e2e：真无头 Chrome，验"拖一下真的落盘了吗"
```

> **前端那两层的分工是后来拆出来的**，理由值得记：
> 折叠算到哪一层、菜单里这一项该不该出现、泳道怎么分——
> 这些以前只能靠 e2e 点开菜单才验得到，**慢，而且失败了只知道"菜单不对"，
> 不知道是哪条判断不对**。拆出纯函数那一层之后，失败信息直接指到判断本身。
> 这条和用不用框架无关，但它是"测试为什么值钱"的那一半。

---

## 4. 触发线

- 需要 **fixture 作用域**（某个昂贵的准备要跨用例复用）；
- 需要**参数化矩阵**（同一逻辑 × 十几组输入，手写 `for` 开始丢失"是哪一组挂了"）；
- 用例多到**必须并行**。

**到那天换 pytest 几乎是无痛的**：用例本身就是普通函数加一个装饰器，
`@case` 换成 pytest 的收集规则即可，断言一行都不用动。
这一点是现在这个写法最大的好处——**它不是"另一套框架"，它是"没有框架"，所以没有迁移成本。**

---

## 5. 代价

- **没有覆盖率数字。** 靠"改哪块补哪块"的纪律顶着，没有客观指标。
- **没有并行。** 全量跑是秒级，现在不疼。
- **三份 runner 的 `main()` 是重复代码**（Python 两份几乎一样）。
  合并过一次的念头，没做——为了让每一处都能单独 `python <file>` 跑起来，不引入跨目录 import。
