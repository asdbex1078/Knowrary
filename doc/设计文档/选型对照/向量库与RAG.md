# 选型对照：向量库 / RAG

> **结论：不用。关键字 + 按词拆 + 一跳邻居，零向量库。**
> 冲突：**约束 1**（md 是唯一真值源）——embedding 要引入第二份会漂移的索引。
> 触发线：节点数过千**且**反复出现"明确记得写过但关键词搜不到"；对话累计超约 5 万轮。
> 代码：`server/chat.py`（`_terms` / `_match` / `_tool_search`）、`tools/knowrary/core/index.py`。
> 判据与总表：《[选型判据](选型判据.md)》。相关：《Agent架构与选型》§9、《第二版设计文档》F10.7。

## 1. 现在是什么

检索的全部实现是十来行（`server/chat.py:113`）：

```python
def _terms(q: str) -> list[str]:
    """查询拆成词；一个词也拆不出来时退回整串。"""
    got = [t for t in SPLIT_Q.split(q.lower()) if t]
    return got or [q.lower()]

def _match(hay: str, terms: list[str]) -> int:
    """命中几个词。0 = 不算命中；命中多的排前面。"""
    low = hay.lower()
    return sum(1 for t in terms if t in low)
```

空格、顿号、逗号、斜杠、加号都算词边界；命中词数多的排前面，同分看图上的度数
（"两个词都中的当然比只中一个的相关；同分的看谁在图里更中心"）。
干草堆是 `id + name + desc + tags + aliases`——**正文不进检索**。

规模：95 个节点、64 条边。

---

## 2. 冲突点：第二份索引，和它的失效问题

embedding 要引入一份**独立于 md 的向量索引**。然后：

- md 改了 → 要重算；
- 改名 / 合并了 → 要重算（这个项目的 rename 已经要同步 5 个文件里的同一个 id）；
- 换个 embedding 模型 → 全量重灌。

这直接冲**约束 1**：md 不再是唯一真值源，旁边多了一份**会漂移、且漂移了看不出来**的副本。
git 看不见它的 diff，Obsidian 打不开它，坏了不能肉眼修。

---

## 3. 力气花在了哪：把假阴性说清楚

**真正的检索问题不是"找不到"，是"图里根本没建"。** 所以两处补丁比提高召回率便宜得多：

**其一，连"还没建出来的点"一起搜。** 一个项目常常 40 个点里 39 个只活在 `projects.json` 里。
只搜索引的话，问"图里有没有多头注意力"会得到零命中，而 Transformer 项目里明明就列着它——
于是又建一个重复的。**计划里的点和已建节点是同一件事的两个阶段。**

**其二，零命中时明说边界**：

```python
return (f"按 {'、'.join(terms)} 这几个词，标题 / 描述 / 别名 / 标签里都没有匹配的"
        f"（**正文没进检索**，所以这不等于图里没写过）。"
        f"换个更短的词再搜一次，或者直接问我。", {"hits": 0})
```

否则模型会把"没搜到"直接讲成"你图里没有"，然后据此往下推。

> **不拆词那次更典型**：问一句「符号主义 连接主义」必然零命中（字面全串匹配），
> 模型拿着这个假阴性跑去翻全量项目和今日清单核对，白烧两个来回。
> 修的不是召回率，是"让假阴性自己报出来"。

---

## 4. 对话留档同理

《第二版设计文档》F10.7：**存，但不建库、不切分、不做 embedding。**

两条理由：

- **对话是过程，不是知识。** 切分向量化 = 建第二个可检索语料库，
  和图谱讲同一批知识却各自漂移。
- **检索系统已经存在，就是这张图。** 而 `tech-doc`（对话 → 讲解文档）与
  `knowrary-import`（对话 → 节点）两个 skill 的存在前提正是"**原文沉淀完可以扔**"。
  **再建 RAG 等于把这两个 skill 否掉**——那才是这个产品真正的检索路径：
  值得留的东西应该被拆成节点进图，而不是原样躺在一个向量库里等人去捞。
- **量级差两个数量级。** 每天 10 轮 × 一年 = 3650 条，`rg` 是毫秒级的。
  向量检索的门槛是"语料大到人翻不动 + 关键词召回不足"；
  代价是切分策略、模型选型、向量库、索引重建、换模型重灌。

落地是一行一轮 JSONL、按月分文件、`.gitignore` 排除。

> 中间那条是这一整篇里最硬的一条，值得单独记：
> **不是"现在还不需要 RAG"，是"建了 RAG 就等于承认知识可以不进图"** ——
> 而"把学到的东西拆成节点连上线"正是这个产品的全部主张。

---

## 5. 触发线

- **知识层**：节点数过千，**且**反复出现"明确记得写过但关键词搜不到"。
  两个条件要同时满足——只是节点多不构成理由，关键词能召回就不需要第二套。
- **对话**：累计超过约 5 万轮（现在三位数），或反复出现"明确记得聊过但 `rg` 找不到"。

---

## 6. 代价

- **同义词召回不了。** 写的是"注意力机制"，搜"attention" 能中（`aliases` 里有），
  但搜"聚焦"就不行。现在靠 `aliases` 和 `tags` 人工兜——
  导入时的「线头」抄进 `tags` 就是为了以后建到那个点时能搜回来。
- **正文不进检索。** 这是刻意的（进了就要面对"匹配到正文第 800 字怎么展示"），
  代价由 §3 那句提示兜住：明说"这不等于图里没写过"。
