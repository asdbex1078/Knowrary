# 选型对照：进来了的那些

> **结论：用。它们各自冲 0 条约束。**
> 这一篇存在的理由：**判据要能输出"用"，否则它就是偏好不是判据。**
> 判据与总表：《[选型判据](选型判据.md)》。

前面几篇都是"不用"。如果这套判据只会输出"不用"，那它不是判据，是"什么都自己写"的托词。
所以这一篇把进来的依赖逐个对一遍——**同一把尺子，量出相反的结论。**

---

## 1. 逐个对

| 依赖 | 干什么 | 冲突 | 备注 |
|---|---|---|---|
| **FastAPI / uvicorn** | HTTP 路由、SSE | 0 条 | 不碰真值源、不碰消息列表、不碰渲染上界 |
| **pydantic** | 请求校验 | 0 条 | 校验发生在入口，落盘那一侧另有四层闸 |
| **watchfiles** | 文件监听（Obsidian 与本系统并发编辑） | 0 条 | **恰恰是为约束 1 服务的**：因为 md 可以被外部改，才需要监听 |
| **X6** | 画布交互层：拖拽、框选、对齐线、历史、分组 parent/children | 0 条 | **前提是节点自己画**（见《[画布节点渲染](画布节点渲染.md)》）。用它的交互，不用它的组件模型 |
| **Vue 3 + Vite** | 面板、托盘、Digest、卡片、对话区 | 0 条 | 构建产物提交到 `web/dist/`，**运行期零 Node** |
| **marked / mermaid** | 正文与图表渲染 | 0 条 | 纯展示层，不碰 md 源 |
| **@antv/hierarchy、@antv/algorithm** | 布局与图算法 | 0 条 | 纯函数，输入图输出坐标 |
| **anthropic SDK** | 流式（**可选**，装了才用） | 0 条 | 见《[LLM-SDK](LLM-SDK.md)》 |
| **httpx2 / pyflakes** | 测试与静态检查（dev-only） | 0 条 | 不进运行期 |

---

## 2. 共同点

**它们都是"某一层的实现"，不是"整体的组织方式"。**

- FastAPI 决定"一个 HTTP 请求怎么进来"，不决定你的领域模型长什么样；
- X6 决定"鼠标拖动时元素怎么跟手"，不决定图里有什么；
- marked 决定"`**粗体**` 怎么变成 `<strong>`"，不决定正文写什么。

而 agent 框架决定的是**循环怎么转、消息怎么攒、工具怎么绑**——那是组织方式。
ORM / 数据库决定的是**真值住在哪**——那也是组织方式。

> **一个依赖越想决定你的代码怎么组织，它和四条约束撞上的概率就越大。**
> 这大概就是判据背后真正的东西：不是"少用依赖"，是"别把组织方式外包出去"。

---

## 3. 两处"用了但划了线"

这两处最能说明判据是怎么用的——**不是二选一，是划清分工。**

### 3.1 X6：用交互，不用组件模型

X6 的节点可以是自定义组件，这里不用；但它的拖拽、框选、对齐线、撤销历史、
分组的 parent/children 全都在用。

**线划在"会不会被画几千个"上。** 交互逻辑只有一份，节点有几千个。

### 3.2 Vue：用在面板，不用在节点

同一条线。面板类 UI 全是 Vue 组件，画布上的东西一个都不是。

> 还有第三处更隐蔽的："**构建产物入库、运行期零 Node**"。
> Vue 和 Vite 只在构建期出现，`web/dist/` 直接提交。
> 这让"拿到仓库就能跑"成立——和测试不用框架、LLM 后端不强依赖 SDK 是同一条线：
> **零配置启动不是省事，它是这个项目能被别人用起来的前提。**

---

## 4. 什么会让某一条被重新评估

- **X6**：如果哪天全局图真的要上万节点，X6 那一层会被 WebGL 换掉
  （第一版本来就是"WebGL 全局图 + X6 局部编辑"的双层架构）。
  现在 95 个节点，双层是过度设计，所以只留了 X6 那一层。
- **Vue**：没有触发条件。它只管面板，面板不会变成瓶颈。
- **FastAPI**：没有触发条件。
