# 字段与术语

> 写产品文档、用户指引时查**术语表**；改代码、看 JSON 时查**字段字典**。
> 两栏必须对得上——分成两份文档维护，迟早漂移成两套说法。

这份文档解决的是一个具体的坑：同一个东西，界面上叫「标准答案」，契约里叫 `ref_answer`，
题库 JSON 里还曾经叫 `answer`，而 `answer` 这个词又容易被读成"我的回答"。
每新增一个字段，**同时**在这里补一行，别等下次被问住。

---

## 一、命名约定

1. **名字要答得出"谁写的"。** 一个字段如果分不清是我写的、模型写的、还是程序算的，
   就不算命名好。`my_answer` / `ref_answer` / `full_answer` 三个名字的区别正是来源，不是长短。
2. **来源不同的两份数据不许合并成一个字段。** 想省事就加 `*_src` 标来源，
   不要让可信的和不可信的挤在同一个键里——合并之后再也拆不开。
3. **派生字段不进真值文件。** md 是真值，`index.json` 是派生缓存，md 一改就全量重建；
   把状态写进 index 等于下次重建时被覆盖。
4. **枚举值用中文、存原文，不存代号。** 这个库是给人看的，`"记得"` 比 `"grade": 2` 直观，
   而且 Obsidian 里直接读 md 也认得。
5. **id 只许 ASCII，显示名另存 `name`。** id 会变成文件名和目录名，中文 id 迁起来是灾难。
6. **改名必须留迁移代码 + 改名记录**（见文末第五节），旧数据不许因为一次改名作废。

## 二、术语表（写文档 / 做用户指引时查这里）

| 用户看到的词 | 代码字段 / 常量 | 一句话定义 |
| --- | --- | --- |
| 知识点、节点 | `nodes/**/*.md`、`IndexNode` | 一个概念一个 md 文件，文件名就是 id |
| 关系、边 | `- 类型:: [[目标]]`、`IndexEdge` | 写在源文件 `## 关系` 段里的带类型链接 |
| 关系族 | `family` | 26 种关系类型归到 5 个族，渲染和分析只认族 |
| 领域 | `field` | 这个知识点属于哪一块（AI / 计算机系统…），决定画布分组 |
| 抽象层 | `layer` | 从理论到应用的 7 层，决定节点落在哪条泳道 |
| 占位 / 只有壳 | `stub` | 被别人链接过、自己还没有 md 的节点 |
| 项目 | `projects.json` 的一条 | 一次学习目标（如"搞懂 Transformer"），底下挂若干清单 |
| 清单 | `lists[]` | 项目下的一条学习线，分阶段、每阶段列知识点 |
| 难度档 | `level`（了解 / 会用 / 精通）| **学到什么份上**。决定出题多深、判分多严、拆点多细 |
| 学习负荷 | `load`（轻 / 中 / 重）| 一个知识点大概要花多少工夫，用来排时间账 |
| 掌握度 | 未建 / 只有壳 / 待复习 / 学过 / 已掌握 | 一个知识点当前的状态，项目进度按它算 |
| 复习档位 | `grade`（记得 / 模糊 / 忘了）| 答完一题我给自己打的分，**喂遗忘曲线的唯一输入** |
| 间隔序号 | `step` | 复习到第几档，对应 1/2/4/7/15/30 天 |
| 题干 | `stem` | 一道题的问题本身 |
| 标准答案 | `ref_answer` | **照我笔记正文抄的**那份答案，判分依据 |
| 我的作答 | `my_answer` | 我答题时写下的，只留档、不进题库 |
| 完整答案 | `full_answer` | 批改时模型补的完整版，**允许超出我的笔记**，只给我看 |
| 笔记里没有 | `beyond_vault` | 完整答案里超出我笔记的那些点，核实后可补进节点 |
| 答超了 | `beyond` | 这题答到了上一档的水准，提示可以升档（**不加分**）|
| 题库 | `question-pool.json` | 攒下来的题，出题先查这里，够数就不调模型 |
| 错题本 | `wrong_nodes()` | 不是独立数据，是答题事件流按节点聚合出来的 |

## 三、字段字典

### 契约一：Markdown（**真值**，其他全是它的派生）

写入口：`/api/changes`（ChangeSet）与我在 Obsidian 里手改。**程序不许绕过 ChangeSet 写 md。**

**frontmatter**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 显示名。id 是文件名，这个是给人看的 |
| `field` | 是 | 领域，决定画布分组 |
| `desc` | 是 | 一句话摘要。出题、悬浮卡、索引都用它 |
| `layer` | 否 | 抽象层，见枚举表；不填落「未分层」 |
| `year` | 否 | 出现年份，历史视图按它排时间线 |
| `learned` | 否 | 学会的日期。**没有它就不进复习调度** |
| `source` | 否 | 来源（书、论文、文章链接）|
| `tags` | 否 | 自由标签 |
| `aliases` | 否 | 别名，聊天时靠它认出我说的是哪个节点 |
| `type` | 否 | 节点类型 |
| `status` | 否 | 默认 `active` |

**`## 关系` 段**：每行 `- 类型:: [[目标]] (年份) — 备注`。类型必须在 `relation-types.json` 里登记，
未登记的落 `弱关联` 族并产生警告。边**只写在源文件**，反向边由 `inverse` 推出，不重复写。

### 契约二：`.knowrary/index.json`（派生缓存，服务只读）

由 `build_index` 全量重建，`content_hash` 决定 `revision`。**任何状态都不许写进这里**——下次重建就没了。

顶层：`schema_version` / `revision` / `generated_at` / `content_hash` / `nodes` / `edges` /
`families` / `stubs` / `stats` / `errors` / `warnings`

| 节点字段 | 说明 |
| --- | --- |
| `id` `path` `digest` | id 即文件名；`path` 是 vault 相对路径；`digest` 是内容指纹 |
| `name` `field` `desc` `layer` `year` `learned` `source` `tags` `aliases` `type` `status` | 直接来自 frontmatter |
| `out` / `in` | 出边、入边的目标 id 列表 |
| `degree` | 出入边总数 |
| `rank` / `weight` | `rank` 是 PageRank 原值（全图总和为 1），`weight` 是它归一到 0~1 的版本，前端直接拿来定节点大小 |
| `stub` | true = 被链接过但没有 md |

| 边字段 | 说明 |
| --- | --- |
| `id` `source` `target` `type` | 边本身。`type` 归一到 canonical 正向类型 |
| `family` | 5 个族之一，渲染与分析只认它 |
| `note` `year` | 备注与年份 |
| `symmetric` | true = 无方向（如「对比」）|
| `declared_in` | 这条边写在哪个文件里 |

### 契约三：`.knowrary/layout.json`（画布，用户数据）

唯一写入口 `PATCH /api/layout`，带 `base_revision` 乐观并发。**改 layout 不碰 md，改 md 不动 layout。**
项目各自的画布在 `.knowrary/layouts/<project>.json`，形状相同。

`viewport{zoom,cx,cy}` / `groups{}` / `nodes{}` / `refs[]` / `notes[]` / `images[]` / `edges{}`

| 分组字段 | `name` `x` `y` `w` `h` `parent` `collapsed` `pinned` `color` `doc` |
| --- | --- |
| **节点框** | `x` `y` `w` `h` `group` `state`(final/draft/ghost) `placedAt` `anchor` |
| **边样式** | key 为 `源->目标#类型`，值 `{vertices[], router}`；只存我手工调过的 |

`state: ghost` = 计划里有、图里还没建的占位，**只出现在项目画布**，不进全局 layout、不进 vault。

### 契约四：`.knowrary/review-log.json`（复习状态）

唯一写入口 `record_review()`（交卷、`/api/review/:id`）。调度每次全量读，必须保持紧凑。

| 字段 | 说明 |
| --- | --- |
| `nodes.<id>.reviews[]` | 每次复习 `{date, grade}` |
| `nodes.<id>.step` | 间隔序号，对应 `INTERVALS` 的天数 |
| `nodes.<id>.lapses` | 答「忘了」的累计次数 |
| `nodes.<id>.next_due` | 下次到期日 |

### 附属数据

**`.knowrary/quiz-log.json`** — 答题**事件流**，只追加。和 review-log 的分工：那边是状态、要紧凑，这边是历史、只在回看和统计时读。

`answers[]`：`ts` `points[]` `type` `stem` `ref_answer` `my_answer` `grade` `missed[]` `wrong[]`

> 2026-09-16 之前的老记录里 `ref_answer` 还叫 `answer`，历史不回写（没有任何地方读它）。

**`.knowrary/quiz-open.json`** — 出了还没交的那份卷子。出题花过钱，刷新页面不该让它没了。交卷或明确放弃才清。

`created` `questions[]` `index_revision` `style`(复习/面试) `level`

**`.knowrary/question-pool.json`** — 题库。出题先查这里，够数就一次模型都不调。

| 字段 | 谁写的 | 说明 |
| --- | --- | --- |
| `stem` | 模型 | 题干。判重按规整后的题面（忽略空白标点）|
| `ref_answer` | **我的笔记** | 标准答案，出题时照正文抄，或批改时照正文补。**只填空，绝不覆盖** |
| `ref_src` | 程序 | `vault` = 批改时照正文补的 |
| `full_answer` | 模型 | 完整答案，允许超出笔记。**每轮覆盖**，越答越好 |
| `beyond_vault[]` | 模型 | 完整答案里超出笔记的点，核实后可补进节点 |
| `full_src` | 程序 | `llm` = 这份是模型写的，回看时要分得出来 |
| `points[]` | 模型 | 考点节点 id。没有考点的题进不了池子（抽查是按节点找题的）|
| `source` | 程序 | `chat` = 聊天时教练问的；`quiz` = 出题时模型编的 |
| `asked` `right` `wrong` `last` `learned` | 程序 | 问过几次、对错、最近一次；`learned` 只是排序提示，不是"以后不考了" |

**`.knowrary/projects.json`** — 项目与清单。

项目：`name` `created` `field` `level` `weekly_hours` `daily_quota` `legacy_id` `lists[]`
清单：`kind`(学习/面试/领域) `level` `name` `goal` `coach` `field` `target_date` `stages[]`
阶段：`name` `deadline` `points[]`；知识点：`id` `name` `why` `load`

> 清单的 `level` 可以覆盖项目的 `level`；都不填走默认档「会用」。

**`.knowrary/llm-usage.json`** — 模型用量。`totals` / `by_day` / `by_op` / `recent[]`，
每档都是 `calls` `errors` `cost_usd` `ms` `input_tokens` `output_tokens` `cache_read_tokens` `cache_write_tokens`。
`op` 取值：`quiz` / `quiz-interview`（按考法分）、`quiz-diagnose`、`chat-<立场>`（如 `chat-教练`）、
`suggest`、`merge`、`plan-propose` / `plan-interview` / `plan-map`（按清单类型分，见 `server/projects.py` 的 `OPS`）。

**`.knowrary/plans.json`** — v1 遗留，读成 v2 的 `projects` 且**不回写**。

## 四、枚举值

| 枚举 | 取值 | 默认 | 定义位置 |
| --- | --- | --- | --- |
| 抽象层 `layer` | 理论 / 硬件 / 体系结构 / 汇编接口 / 系统软件 / 高级语言 / AI应用 | 未分层 | `core/parser.py` |
| 关系族 `family` | 结构 / 依赖 / 演化 / 对照 / 弱关联 | 弱关联 | `relation-types.json` |
| 难度档 `level` | 了解 / 会用 / 精通 | 会用 | `core/projects.py`，口径在 `server/levels.py` |
| 复习档位 `grade` | 记得 / 模糊 / 忘了 | 记得 | `core/review.py` |
| 掌握度 | 未建 / 只有壳 / 待复习 / 学过 / 已掌握 | — | `core/projects.py` |
| 学习负荷 `load` | 轻 1.0h / 中 2.5h / 重 5.0h | 中 | `core/projects.py` |
| 清单类型 `kind` | 学习 / 面试 / 领域 | 学习 | `core/projects.py` |
| 考法 `style` | 复习 / 面试 | 复习 | `server/quiz.py` |
| 复习间隔 | 1 / 2 / 4 / 7 / 15 / 30 天 | step 0 起 | `core/review.py` |
| 时间账 | 充裕 / 紧 / 不可能 | — | `core/projects.py` |

**难度档决定三件事**：出题问多深（`levels.quiz`）、判分多严（`levels.judge`）、拆点多细（`levels.plan`），
外加聊天展开到哪一层（`levels.chat`）。出题和判分**必须用同一档**——出题按「了解」问、
批改按「精通」判，会让我为一个只要了解的点白白多复习一轮。
