# Day-Info 定时任务配置归档

> 这里保存「AutoClaw 定时任务」的完整配置与提示词，便于查看、复用或迁移到其他环境。

## 任务一览

| 任务 | 调度（Asia/Shanghai） | 作用 |
| --- | --- | --- |
| Day-Info 每日收集（静默入池） | 每天 09:00 | 采集 15 个信息源 → 三档打标 → 存入 `pool/` → 提交并推送本分支；**不向用户推送内容** |
| Day-Info 周报·生成 | 每周日 19:45 | 合并最近 7 天收集池 → 精编周报 → 写入 `digests/` 并推送分支（不输出全文） |
| Day-Info 周报·阅读版 | 每周日 20:15 | 读取周报全文并输出（阅读版）|

三个任务都在**隔离会话**（isolated）中运行，最长执行 5 分钟（`timeoutSeconds: 300`）。

> 周报为何拆两段：早期单任务版实测连续 4 次超时（生成周报全文 + 输出在同一次执行里超过 5 分钟上限），
> 拆成"生成（只写文件）"+"阅读（只读文件输出）"后各段都能在时限内完成。

## 文件

| 文件 | 内容 |
| --- | --- |
| `openclaw-cron-jobs.json` | 两个任务的完整配置（调度、会话目标、delivery、payload 含完整提示词） |
| `prompt-daily.md` | 每日收集任务提示词（可读版，含设计说明） |
| `prompt-weekly.md` | 周报任务提示词（可读版，含设计说明） |

## 如何迁移 / 重建

在另一台 AutoClaw 环境：

1. 克隆本仓库并把工作区放到 `Knowrary-dayinfo`（或任意路径后调整提示词里的绝对路径）。
2. 参照 `openclaw-cron-jobs.json`，用 AutoClaw 的定时任务面板（或对话说"创建一个每天 9 点的任务"）重建两个任务；提示词直接复制 `payload.message`。
3. 推送凭证按 `day-info/README.md` 的「推送凭证」一节配置（PAT 或 Deploy Key 二选一）。

> 提示词中出现的 `/root/.openclaw-autoclaw/workspace/Knowrary-dayinfo` 是当前环境的绝对路径，迁移时替换为目标环境的实际路径即可。

## 设计要点（为什么这样拆）

- **收集与推送分离**：收集任务每天跑但不打扰；周报任务每周一次只做精选输出——「收集频率高，推送频率低，形成漏斗」。
- **critical 即时提醒**：每日收集的输出里若有 `CRITICAL:` 行（项目强相关或头部实验室重大发布），会被整理为「⚡【即时提醒】」。
- **双任务共享脚本**：采集逻辑在 `scripts/collect.py`（零依赖），提示词只做"调用 + 汇报"，降低模型自由发挥的空间。
