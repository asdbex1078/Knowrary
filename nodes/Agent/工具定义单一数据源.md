# 工具定义单一数据源

## 描述

给 LLM 配工具时有三份东西要保持一致：

1. **说明书**——提示词里那张"你有哪些工具"的表；
2. **JSON Schema**——真正发给模型的工具定义；
3. **白名单**——服务端允许执行的那一份。

**它们必须从同一份数据渲染出来，不能各写一遍。**

## 核心内容

### 为什么

"**表里写着能用、调了却说没有**"是最让人发火的那种 bug：
模型照着说明书调，服务端说没有，模型不知道自己错在哪，于是换个参数再试一遍——
每试一次就是一个完整的来回。

两边各写一遍，迟早对不上。尤其是加了开关之后：某一档关掉时，
提示词里的那段说明和 schema 里的工具定义要**同时**消失，漏一处就是上面那个 bug。

### 一份数据，三个用途

```python
tools   = tools_of(stance, vault)          # 白名单
table   = 从 spec 渲染的说明书                # 提示词里那张表
schema  = tool_schemas(tools)              # 发给模型的工具定义
```

加一档口径、关一个开关 = 白名单元组里少两个名字，**没有第二处要改**。

### schema 说得清形状，说不清纪律

类型、必填、参数含义交给 schema；但这些只能用散文写：

- "什么时候该追加、什么时候该整段替换"
- "互不相关的几件事要拆成几次提"
- "正文要写到什么份上"

所以 schema **没有取代**那份散文格式说明，两者分工不同。

### 关掉一个能力时，要真收走，不是叮嘱一句

关掉某一档时，相关的提示词段落**整段不渲染**，相关工具**真的从白名单和 schema 里消失**——
而不是留着工具再叮嘱一句"别用"。

> **手段还在手里、只靠一句话拦着，那是压制不是关闭。**

配套的一条：关掉时只补**一句事实**，不补"不要做 X"——
规矩已经不渲染、工具已经收走，再写一串禁令就是在提醒它有这回事。

## 线头

- 能力边界写在服务端、不写在提示词里：提示词会被绕过，白名单不会。
- 调了白名单外的工具该怎么回，见 [[工具错误说给模型听]]。
