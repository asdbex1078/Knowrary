## 描述

包在 LLM 调用和工具调用外面的那一层运行时。**模型只负责「下一步说什么」，
其余全是它的事**：循环转几轮、工具怎么分发、上下文裁到多长、
取消信号往哪送、崩了怎么恢复。

## 核心内容

### 它管的是「模型管不了的那一半」

    模型：给一段文本 / 一次工具调用
    Harness：决定要不要再来一轮、调哪个工具、把结果怎么喂回去、什么时候停

**终止条件也在这一层**：不再调工具就是终止，不需要模型发一个 finish 信号。

### 硬边界写在这里，不写在提示词里

提示词会被绕过，**工具白名单不会**。所以「这一档能用哪些工具」是 Harness 的事，
而 [[工具定义单一数据源]] 说的就是这份白名单必须和说明书、JSON Schema 同源。

工具出错也归它兜：[[工具错误说给模型听]] 那三条非正常路径——调了表外工具、
同参数重复调用、工具自己炸了——**一条都不抛异常**，全都翻译成话说给模型听。

### 上下文的形状归它

单轮 prompt 的上界由代码封顶（图谱再大、笔记再长都不变），
而消息列表怎么攒直接决定账单：见 [[消息列表只增不改]]。
这一条是 Harness 层最容易做错、又最不容易被发现做错的地方——
[[回合首次前缀失效]] 就是一个不报错、答案全对、只有账单在涨的例子。

### 长程任务的那一整套也在这一层

[[长程Agent最小架构]] 的六个组件（Task Store / Worker / Cancellation Channel /
Operation Log / Recovery Worker / Idempotency Layer）全是 Harness 的组成部分。
[[取消检查点]] 插在它的每一步动作前后，[[崩溃恢复]] 扫的是它写的操作日志。

## 为什么它值得单独是一个概念

因为**同一个模型配不同的 Harness，能力差别比换模型还大**：
能不能用工具、能不能中断、崩了能不能接着跑、贵不贵，全在这一层。
而它又常常被当成「胶水代码」—— 于是这些能力差异被归因成「模型不行」。
