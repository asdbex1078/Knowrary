# 内存墙

## 描述
算力涨得比带宽快，导致大模型推理是访存瓶颈而不是算力瓶颈。

## 两类墙（别混着说）

- **带宽墙**：decode 每生成一个 token，都要把全部权重 + 全部历史 KV 从显存读一遍，算术强度（FLOPs/字节）极低 → 算力大量闲置，bandwidth-bound。
- **容量墙**：KV cache 随上下文长度线性增长，把显存吃光 → batch 上不去、上下文长度受限。

两者都落在 KV 上，但要的东西不同：带宽墙要「每个 token 少读点字节」，容量墙要「少占点显存」。MQA/GQA/MLA 一招同时缓解两个（KV 头变少 → 读得少也存得少），所以这两类墙容易被当成一件事。

## 边界

- **prefill 不在这堵墙里。** 整段 prompt 一次性并行算，算术强度高，是 compute-bound。「内存墙」专指 decode 阶段。
- **「MQA/GQA/MLA 存在的唯一理由」这句太满。** 它们确实是冲着 KV 去的，但同期打同一堵墙的还有量化（权重/KV 低精度）、PagedAttention（显存碎片）、offload。说「主要动机」比「唯一理由」准。

待补：量化 / PagedAttention / offload 各自打的是带宽还是容量，我还没分清。

> **年份锚点：1995。** Wulf & McKee《Hitting the Memory Wall: Implications of the Obvious》，
> ACM SIGARCH Computer Architecture News 23(1)，1995-03——「内存墙」一词的出处。
> 原文讲的是 CPU 与 DRAM 的速度差距按指数拉开；上面写的是它在大模型 decode 上的现代形态。
